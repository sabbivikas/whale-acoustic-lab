# Governance

Whale Acoustic Lab currently uses a maintainer-led governance model.

## Maintainer

Vikas Sabbi is the project owner and maintainer. The maintainer:

- sets product and release direction;
- reviews and accepts contributions;
- protects scientific, privacy, security, accessibility, and licensing
  boundaries;
- approves changes to algorithms, schemas, reference data, models, and
  provider integrations; and
- decides when a release is ready.

## Decision process

Ordinary changes may be proposed through GitHub Issues and pull requests after
the repository becomes public. Changes to scientific calculations, data
provenance, privacy boundaries, model routing, or export schemas require
documented rationale, tests, and explicit maintainer approval.

Disagreement should be resolved through evidence, reproducible tests, and
clear documentation of uncertainty. The maintainer makes the final decision
when consensus cannot be reached.

## Security and sensitive conduct reports

Do not disclose vulnerabilities or sensitive conduct reports in an Issue.
Follow [SECURITY.md](SECURITY.md) and [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
The repository must have GitHub Private Vulnerability Reporting enabled before
public participation begins.

## Governance changes

The maintainer may expand this model when the contributor community grows.
Material governance changes will be documented in this file.
